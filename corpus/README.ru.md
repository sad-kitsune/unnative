# Тестовый корпус

[English](README.md) | **Русский**

Небольшие программы на Java, используемые как тестовый материал. Каждая программа
затрагивает одну область спецификации JVM. Мы собираем каждую из них без защиты
(базовый вариант) и — там, где протекторы доступны — защищёнными с помощью JNIC и
JVMTP по матрице опций, после чего сверяем вывод инструмента с базовым вариантом.

- `src/` — программы на Java (под контролем версий).
- `configs/` — конфигурации опций для каждого протектора (см. матрицу ниже).
- `build/`, `out/` — результаты сборки и записанный ожидаемый вывод (в .gitignore).
- `build.sh` — собирает базовые варианты и записывает их вывод; также собирает
  защищённые варианты, когда протекторы настроены.

## Сборка

```sh
corpus/build.sh                                                  # только базовые
JNIC_CLI=/path/to/jnic JVMTP_CLI=/path/to/jvmtp corpus/build.sh  # + защищённые
```

Базовые сборки компилируют каждый `src/<Name>.java`, упаковывают его в jar с
`Main-Class`, запускают и сохраняют stdout+stderr+код возврата в
`out/expected/<Name>.txt`. Этот записанный вывод — эталон, с которым затем
сравнивается пересобранный jar.

## Программы

| программа | что затрагивает |
|---|---|
| `ArithEdges` | переполнение int, idiv/irem на ноль, маскирование сдвигов, сравнение long, NaN, насыщение d2i |
| `Exceptions` | вложенные try/catch/finally, finally на каждом пути, повторный выброс с причиной |
| `Switches` | tableswitch, lookupswitch, switch по String, switch по enum |
| `Indy` | lambda metafactory (с захватом и без), конкатенация строк через `invokedynamic` |
| `Invokes` | все виды `invoke*`, методы по умолчанию, `super`, доступ к полям и статике, `new` |

Стоит добавить: массивы (многомерные, ковариантность), `synchronized`/мониторы,
порядок `<clinit>`, дженерики + мостовые методы, вложенные/анонимные классы,
рекурсию, varargs, рефлексию. Положите по одному `.java` на каждую область в `src/`,
и `build.sh` подхватит его автоматически.

## Матрица опций (`configs/`)

Для каждой программы собрать:

- **базовый вариант** — без обфускации (также эталон для восстановления потока
  управления).
- **каждую опцию по отдельности** — по одному переключателю за раз, чтобы сбой
  указывал на конкретную функцию:
  - JNIC: `stringObf`, `flowObf`, `useIntrinsics`.
  - JVMTP: `obfuscation.constants.mba`, шифрование строк, сокрытие вызовов,
    непрозрачные предикаты, уплощение (flattening), `obfuscation.jumps`,
    `resources.compress`, `compiler.batch-resolve`, `compiler.safe-env`,
    `antidebug.enable`.
- **всё включено**.
- **VM-бэкенд JVMTP** — `vm.stack`, `vm.register`, `vm.dual`.

Записывайте версию протектора в имя каждого выходного файла, например
`out/jvmtp-1.4.2/Switches.vm-dual.jar`, чтобы смена версии проявлялась как diff.

Конкретные форматы конфигурационных файлов заполняются, когда появляется
документация протекторов; здесь они не угадываются.

> **Разрешение.** Соблюдайте условия лицензий протекторов при сборке защищённых
> корпусов и анализируйте только те jar-файлы, на анализ которых у вас есть
> разрешение.
