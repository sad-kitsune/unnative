# unnative

[English](README.md) | **Русский**

Восстановление читаемого Java-кода из jar-файлов, в которых тела методов заменены
нативным кодом с помощью [JNIC](https://jnic.dev) или [JVMTP](https://jvmtp.dev).

Эти протекторы компилируют выбранные методы JVM в машинный код, пряча их за
`native`-заглушкой, и поставляют результат в виде встроенной библиотеки, которая
привязывает себя при загрузке. Исходный байткод при этом теряется, поэтому чтобы
понять, что делает метод, нужно загрузить нативную библиотеку, отследить вызовы JNI,
которые она выполняет, и поднять их обратно к байткоду. `unnative` — консольный
конвейер, который делает именно это. Парсер class-файлов общий с родственным
проектом [unseed](https://github.com/sad-kitsune/unseed).

## Что он делает

`unnative` прогоняет jar через последовательность стадий. Каждая стадия записывает
обычный файл в рабочий каталог, свой для каждого jar, поэтому результаты можно
просматривать и пересчитывать по отдельности.

- **triage** — разобрать классы, перечислить `native`-методы и загрузчик и сделать
  предварительное предположение о протекторе. Пишет `report.json`.
- **unpack** — извлечь встроенные нативные библиотеки на диск. Библиотеки,
  поставляемые как обычные ресурсы jar, извлекаются напрямую; протекторы,
  упаковывающие их в зашифрованный блоб, пока не распаковываются, поэтому можно
  также передать заранее извлечённые библиотеки через `--lib`.
- **bind** — сопоставить каждому `native`-методу функцию, которая его реализует: как
  разрешением экспортируемых символов `Java_*`, так и запуском регистрационного кода
  библиотеки в эмуляторе для перехвата таблиц `RegisterNatives`. Пишет
  `bindings.json`.
- **trace** — выполнить каждый привязанный метод в эмуляторе и записать
  последовательность вызовов JNI и возвращаемое значение. Пишет `trace.json`.
- **deobf** — восстановить скрытые MBA-константы и непрозрачные константы из
  нативного кода. Для каждой привязанной функции он поднимает прямолинейный целочис-
  ленный код каждого базового блока в выражение над регистрами и сворачивает его;
  регистр, который выглядит зависящим от входных данных, но всегда сворачивается к
  одному значению, — это скрытая константа, и она записывается. Подъём надёжен, а не
  полон: всё, что он не умеет моделировать, обнуляет (помечает неизвестными) регистры,
  которые эта инструкция пишет, — поэтому восстановленная константа реальна, а не
  догадка. Пишет `deobf.json`. **Строки здесь вне области действия**: keyed-by-caller
  шифрование Java-строк в этих jar восстанавливает родственный инструмент
  [unseed](https://github.com/sad-kitsune/unseed) (`unseed patch <jar>`), и `unnative`
  намеренно его не переизобретает. Нужен capstone, как и для `lift`.
- **lift** — распознать идиомы JNI в каждой трассе (`GetMethodID` + `Call*Method` —
  это `invoke*`, `AllocObject` + `<init>` — это `new`, доступ к полю, `throw`, …) и
  выдать IR уровня JVM. Если установлен capstone, IR каждого метода дополнительно
  обогащается графом потока управления, восстановленным статически из его нативного
  кода, — базовые блоки, рёбра, циклы и любой косвенный переход, оставленный как
  открытый выход. Пишет каталог `jir/`, по одному файлу на метод, со сводкой
  покрытия. Для прямолинейных методов, все операнды которых — отслеживаемые ссылки
  или восстановленные константы (семейство `throw new X()`, а также `obj.m(…)` /
  `System.out.println("…")` со строковыми литералами, восстановленными из трассы), —
  он раскладывает IR на стек операндов и выдаёт кандидатный байткод; с указанием
  причины он отказывается от любого метода, которому нужно значение из нативных
  вычислений, пока ему недоступное (примитив, аргумент метода), значение с несколькими
  использованиями или ветвление. Он пока не восстанавливает чистые вычисления, не
  делающие ни одного вызова JNI. Каждый пробел сообщается по методу, а не скрывается,
  и выданный байткод остаётся кандидатным, пока Phase 8 не сверит его с оригиналом.
- **emit** — пересобрать jar из поднятого IR. Для каждого метода, который стадия
  lift разложила в байткод, заполнить `native`-заглушку: снять `ACC_NATIVE` и добавить
  настоящий атрибут `Code`, записанный небольшим генератором class-файлов на чистом
  Python (без внешнего инструментария — прямолинейным методам, поднимаемым сегодня, не
  нужен StackMapTable). Методы, которые поднять не удалось, остаются нативными
  заглушками, а загрузчик сохраняется, поэтому пересобранный jar по-прежнему
  запускается — частичное восстановление, а не «всё или ничего». У подписанного jar
  подпись снимается, так как перезапись класса делает её недействительной. Пишет
  `rebuilt.jar` и сводку `emit.json`.
- **verify** — дифференциальная проверка пересобранных методов. Для каждого метода,
  заполненного стадией `emit`, восстановленное на стадии lift поведение сверяется с
  двумя независимыми свидетелями: байткодом, заново декодированным прямо из
  `rebuilt.jar` (это ловит порчу на стадии emit), и трассой вызовов JNI эмулированного
  оригинала (эталон, получаемый прослеживанием хэндла брошенного объекта до класса, из
  которого он создан). Если доступен JDK, каждое восстановленное тело также
  запускается на настоящей JVM, и его результат сверяется. Пишет `verify.json` с
  вердиктом по каждому методу. Честное ограничение: оригинальный нативный метод нельзя
  выполнить на месте — инициализация его класса запускает загрузчик протектора, —
  поэтому эмулированная трасса остаётся его единственным независимым свидетелем.

Все перечисленные выше стадии конвейера теперь реализованы; некоторые (`lift`,
`emit`, `verify`, `deobf`) — это первые срезы, которые покрывают конкретные формы и
честно сообщают об остальном, а не угадывают. VM-бэкенд JVMTP, пересобираемый под
каждую сборку (plan.md Phase 9), — отдельное исследование: VM-методы
классифицируются и остаются нетронутыми.

Эмулятор — это процессор [Unicorn](https://www.unicorn-engine.org/) с синтетическими
`JNIEnv`/`JavaVM` и небольшой прослойкой для функций языка C, так что нативная
библиотека выполняется в песочнице, не имеющей доступа к хост-системе.

## Требования

- Python 3.11+ (ядро использует только стандартную библиотеку).
- JDK (17+) для тестовых фикстур и набора тестовых программ.
- Unicorn для эмуляции на стадиях `bind`/`trace`. Статический путь привязки через
  `Java_*` работает и без него.
- capstone — для восстановления потока управления на стадии `lift`. Без него `lift`
  всё равно выдаёт линейный IR, но без CFG по каждому методу.

## Использование

Для работы ядра установка не требуется:

```sh
python3 -m unnative triage path/to/app.jar
python3 -m unnative run     path/to/app.jar
python3 -m unnative --help
```

`run` выполняет стадии по порядку и останавливается на первой ещё не реализованной.
Результаты появляются в `work/<jar>/` (`report.json`, `libs/`, `bindings.json`,
`trace.json`).

Стадиям эмуляции нужен Unicorn. Если `pip` не может установить пакет в системный
Python (например, в конфигурации PEP 668 «externally managed»), используйте
виртуальное окружение:

```sh
python3 -m venv .venv
.venv/bin/pip install unicorn
.venv/bin/python -m unnative run path/to/app.jar
```

Если нативная библиотека упакована так, что `unpack` не может её извлечь, передайте
уже извлечённую библиотеку (флаги указываются после подкоманды):

```sh
.venv/bin/python -m unnative run app.jar --lib linux-x86_64.so
```

Необязательная установка в режиме разработки:

```sh
pip install -e .          # устанавливает консольную команду `unnative`
pip install -e '.[emu]'   # дополнительно устанавливает Unicorn
```

## Тесты

Стандартный `unittest`. Фикстуры собираются на лету с помощью `javac` и компилятора
C; тесты эмулятора пропускаются, если Unicorn не установлен.

```sh
python3 -m unittest discover -s tests
```

## Структура

```
unnative/   пакет: CLI и драйвер, парсер class-файлов, triage, нативный бэкенд

tools/      вспомогательные скрипты
tests/
```
