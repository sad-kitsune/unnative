# unnative

[English](README.md) | **Русский**

Восстановление читаемого Java-кода из jar-файлов, в которых тела методов заменены
нативным кодом с помощью [JNIC](https://jnic.dev) или [JVMTP](https://jvmtp.dev).

Эти протекторы компилируют выбранные методы JVM в машинный код, пряча их за
`native`-заглушкой, и поставляют результат в виде встроенной библиотеки, которая
привязывает себя при загрузке. Исходный байткод при этом теряется, поэтому чтобы
понять, что делает метод, нужно загрузить нативную библиотеку, отследить вызовы JNI,
которые она выполняет, и поднять их обратно к байткоду. `unnative` — консольный
конвейер, который делает именно это. Парсер class-файлов общий с родственным
проектом `unseed`.

## Что он делает

`unnative` прогоняет jar через последовательность стадий. Каждая стадия записывает
обычный файл в рабочий каталог, свой для каждого jar, поэтому результаты можно
просматривать и пересчитывать по отдельности.

- **triage** — разобрать классы, перечислить `native`-методы и загрузчик и сделать
  предварительное предположение о протекторе. Пишет `report.json`.
- **unpack** — извлечь встроенные нативные библиотеки на диск. Библиотеки,
  поставляемые как обычные ресурсы jar, извлекаются напрямую; протекторы,
  упаковывающие их в зашифрованный блоб, пока не распаковываются, поэтому можно
  также передать заранее извлечённые библиотеки через `--lib`.
- **bind** — сопоставить каждому `native`-методу функцию, которая его реализует: как
  разрешением экспортируемых символов `Java_*`, так и запуском регистрационного кода
  библиотеки в эмуляторе для перехвата таблиц `RegisterNatives`. Пишет
  `bindings.json`.
- **trace** — выполнить каждый привязанный метод в эмуляторе и записать
  последовательность вызовов JNI и возвращаемое значение. Пишет `trace.json`.

Более поздние стадии — восстановление обфусцированных строк и констант, подъём
потоков вызовов JNI обратно в байткод, пересборка jar и сверка с оригиналом — пока
не реализованы.

Эмулятор — это процессор [Unicorn](https://www.unicorn-engine.org/) с синтетическими
`JNIEnv`/`JavaVM` и небольшой прослойкой для функций языка C, так что нативная
библиотека выполняется в песочнице, не имеющей доступа к хост-системе.

## Требования

- Python 3.11+ (ядро использует только стандартную библиотеку).
- JDK (17+) для тестовых фикстур и набора тестовых программ.
- Unicorn для эмуляции на стадиях `bind`/`trace`. Статический путь привязки через
  `Java_*` работает и без него.

## Использование

Для работы ядра установка не требуется:

```sh
python3 -m unnative triage path/to/app.jar
python3 -m unnative run     path/to/app.jar
python3 -m unnative --help
```

`run` выполняет стадии по порядку и останавливается на первой ещё не реализованной.
Результаты появляются в `work/<jar>/` (`report.json`, `libs/`, `bindings.json`,
`trace.json`).

Стадиям эмуляции нужен Unicorn. Если `pip` не может установить пакет в системный
Python (например, в конфигурации PEP 668 «externally managed»), используйте
виртуальное окружение:

```sh
python3 -m venv .venv
.venv/bin/pip install unicorn
.venv/bin/python -m unnative run path/to/app.jar
```

Если нативная библиотека упакована так, что `unpack` не может её извлечь, передайте
уже извлечённую библиотеку (флаги указываются после подкоманды):

```sh
.venv/bin/python -m unnative run app.jar --lib linux-x86_64.so
```

Необязательная установка в режиме разработки:

```sh
pip install -e .          # устанавливает консольную команду `unnative`
pip install -e '.[emu]'   # дополнительно устанавливает Unicorn
```

## Тесты

Стандартный `unittest`. Фикстуры собираются на лету с помощью `javac` и компилятора
C; тесты эмулятора пропускаются, если Unicorn не установлен.

```sh
python3 -m unittest discover -s tests
```

## Структура

```
unnative/   пакет: CLI и драйвер, парсер class-файлов, triage, нативный бэкенд

tools/      вспомогательные скрипты
tests/
```

Анализируйте только то ПО, на анализ которого у вас есть разрешение, и соблюдайте
условия лицензий протекторов при сборке тестового материала с их помощью.
